> **이 문서의 성격:**
> `07-memory-architecture.md`와 `RESEARCH-memory-personalization.md`를 읽은 GPT와의 논의 기록.
> 주제: "가중치 고정 LLM에서 컨텍스트 기반 개인화를 어떻게 달성할 것인가"

---

## 대화 1: 컨텍스트 조절 전략

### [나] 문제 제기

내가 현재 만들고 있는 agent의 화두는 **개인화**야.
전세계 많은 연구자들과 기업에서 연구하고 있겠지만, 개인에 맞춰 AI 상품을 만드는 것은 조금만 생각해봐도 어렵다.

1. **개인에게 맞춤 딥러닝을 제공한다** — 기술적/하드웨어적 한계가 있음
2. **이미 존재하는 모델의 context를 잘 조절한다** — context 길이 조절 및 사용자 정보 수집이 극도로 이루어져야 함

2번의 경우 지금 내 상황에서 연구 가치가 있는 것 같다.
대단한 연구를 진행하기보다 나를 대상으로 해볼 거라서 정보 수집 문제는 괜찮고, **context를 조절하는 방법**을 생각해보자.

### [GPT] 분석

지금 고민하는 지점은 그냥 "에이전트 구현"이 아니라 **파인튜닝 없이 개인화 수렴을 설계하는 문제**다.
MLPA 4계층은 아이디어 수준이 아니라 연구 프레임이다.

---

### 핵심 전환: 개인화의 재정의

> 개인화 = "많은 정보를 넣는 것"이 아니라 **"결정 경계(decision boundary)를 바꾸는 것"**

파인튜닝은 가중치를 바꿔 decision boundary를 바꾸는 방식.
우리는 그걸 **외부 구조로 흉내 내야 한다.**

방법은 3가지뿐:

1. **컨텍스트를 넣는다**
2. **입력 전처리를 바꾼다**
3. **출력 후처리를 바꾼다**

현재 구조는 이미 2, 3번을 많이 활용하고 있다.

---

### 전략 1: 컨텍스트를 "양"이 아니라 "위치"로 보기

lost in the middle 문제 — 모델은 앞/뒤를 더 잘 기억한다.

**나쁜 배치:**

```
[system]
[working]
[user_profile]
[episodic]
[user_input]
```

**구조적 배치:**

```
[system: 정체성 + 판단 원칙]
[semantic core: 500tok]
--------------------------
[user_input]
--------------------------
[working state]
[retrieved episode]
```

> 핵심 정보는 항상 상단 고정, 상황 정보는 하단.
> "고정 자아"가 흔들리지 않는다.

---

### 전략 2: Semantic Memory를 "문장"이 아니라 "좌표계"로

USER_PROFILE.md가 서술형이라면, 개인화는 "텍스트 요약"보다 **사용자 벡터화**가 더 적합하다.

```json
{
  "adhd_severity": 0.9,
  "deadline_miss_pattern": 0.8,
  "morning_focus": 0.7,
  "energy_variance": 0.6,
  "impulse_behavior": 0.75,
  "overcommitment_risk": 0.85
}
```

LLM에 넣을 때:

```
사용자 성향 좌표:
- ADHD 심함 (0.9)
- 마감 직전 작업 경향 높음 (0.8)
- 오전 집중력 중간 이상 (0.7)
- 과도한 계획 수립 경향 (0.85)
```

장점:
- 압축 가능
- M4가 수치 조정 가능
- Drift 추적 가능
- 개인화 수렴 곡선 측정 가능

> **문장이 아니라 상태 공간으로 바꿔라.**

---

### 전략 3: Episodic Memory를 "검색"이 아니라 "가중치"로

현재는 Top-K 검색 후 500토큰 주입 구조.

더 나은 방식: **검색 → 패턴 추출 → 패턴만 주입**

| 방식 | 예시 | 토큰 |
|------|------|------|
| 나쁜 방식 | "지난주 화요일 OS과제 3번 미루고 자정에 함" | ~40 |
| 좋은 방식 | "OS과제 유형 → 반복 미루기 패턴 있음" | ~15 |

> 에피소드는 모델이 읽는 게 아니라, **M4가 읽고 패턴을 요약해 주는 것**.

---

### 전략 4: 개인화 수렴의 수학적 프레임

개인화 정확도 P(n):

```
P(n) = 1 - e^(-kn)
```

- n = interaction 수
- k = 패턴 반복 밀도

ADHD 일정 시스템이면 k가 높아 200~300 interaction이면 급격히 수렴할 가능성.

핵심 실험 포인트:
- Layer 0 규칙 증가 → M1 confidence 평균 변화
- USER_VECTOR drift 안정화
- 재질문 빈도 감소 곡선

---

### 컨텍스트를 줄이면서 개인화를 깊게 하는 4단계

```
텍스트 → 수치화 → 패턴 → 코드 → 0토큰
```

이것이 MLPA의 본질이다.

---

### GPT가 제안한 다음 단계

1. USER_PROFILE을 수치 기반 상태 벡터로 재설계
2. M4 Distiller 프롬프트를 완전히 재설계 (증류 전용)
3. Layer 0 규칙 전환 임계값을 수학적으로 설계
4. 개인화 수렴 곡선 실험 설계

> 궁극적 프레임: **"가중치 고정 LLM에서의 외부 기억 기반 개인화 이론"**

## 대화 2: 관련 연구 탐색

### [나] 질문

이미 관련된 비슷한 연구가 많을 것 같은데 참고할 만한 건 없어?

### [GPT] 분석

> 완전히 동일한 구조는 거의 없지만, 부분적으로 겹치는 연구들은 꽤 많다.

참고할 5개 축:

---

### 축 1: Memory-Augmented LLM (외부 메모리 구조)

가장 직접적으로 닿아 있는 분야.

- RAG (Retrieval-Augmented Generation)
- Long-term memory agents
- Vector DB 기반 사용자 기억 시스템

대표 연구/프로젝트:
- **MemGPT** (Berkeley) — MLPA와 가장 비슷한 방향. "LLM 메모리를 계층화하자"
- **Generative Agents** (Stanford Smallville)
- LangChain Memory, LlamaIndex memory modules

**차이점:** MemGPT는 자동 메모리 관리가 핵심. The Agent는 **개인화 수렴과 규칙 전환**이 핵심.

---

### 축 2: Continual Learning (지속 학습)

딥러닝 쪽 키워드: Continual learning, Catastrophic forgetting, Online learning

가중치를 못 바꾸니까 **"External continual learning"** 프레임으로 가져가면 됨.
"학습 안정성" 개념을 설계에 차용 가능.

---

### 축 3: User Modeling / Personalization Systems

추천 시스템/광고 분야 키워드: User embedding, Behavioral modeling, Preference learning, Dynamic user profile

넷플릭스/유튜브가 사용자를 벡터로 표현하는 구조 → **USER_VECTOR 설계에 직접 참고 가능**.

---

### 축 4: Tool-Augmented Agents / Cognitive Architectures

인지 아키텍처 연구: **Soar, ACT-R**

MLPA는 사실상 인지 아키텍처 설계. Working memory, Semantic memory, Procedural memory 구조가 거의 동일.
**인지과학의 기억 모델을 LLM에 이식한 셈.**

---

### 축 5: Self-Improving Agents / Reflection

키워드: Reflexion, Self-refine, Constitutional AI, Critic models

특히 **Reflexion** 논문 — M4 Distiller 개념과 닮음.
차이: 기존 연구는 task-level 개선, The Agent는 **life-level 개인화**.

---

### 핵심 차별점

기존 연구 대부분: **"Task 성능을 올리기 위한 메모리"**
The Agent: **"특정 개인의 decision boundary를 바꾸는 구조"**

### 독창성 포인트

> **"코드 규칙 전환을 통한 0토큰 개인화 축적"** — 이걸 체계화한 연구는 거의 없다.

## 대화 3: 진짜 원하는 것 정의

### [나] 방향 재정립

정확히 짚고 가야 할 것 같다. 내가 직접적으로 원하는 건:

- 나에게 맞춤형 비서 노릇을 **진짜** 할 수 있게
- 단순한 작업부터 내 일상에 깊게 녹아든 일들까지
- 나에게 맞춰 유연하게 일처리를 할 수 있어야 함
- 그러려면 나와 내 주변 일상에 대한 **깊은 이해**가 필요
- 가중치 고정 LLM 위에서 만들려는 것

그리고 이걸 이루려면 **당장 눈앞에 직면한 문제가 뭔지**, 지금 내가 언급한 것들이 정확한 포인트를 짚고 있는지 생각해보자.

### [GPT] 분석: 원하는 것의 구조

> 나를 대신해 판단해주고, 나보다 나를 더 잘 기억하고, 내가 망하기 전에 개입하는 비서

이것을 3가지 영역으로 분해:

| 영역 | 핵심 기능 | 기술 영역 |
|------|----------|----------|
| **(A) 자동 처리** | 일정 자동 구조화, 반복 작업 배치, 에너지 기반 시간 배치, 우선순위 자동 조정 | 패턴 학습 + 규칙화 |
| **(B) 상황 판단** | 지금 이걸 하는 게 맞는지, 미루기 패턴 반복 감지, 개입 필요 여부 판단 | 사용자 모델 기반 판단 |
| **(C) 장기 개입** | 일정 누락 감소, 과제 제출율 증가, 충동성 제어, 과도한 계획 방지 | 행동 수정 시스템 |

---

### 가중치 고정 LLM에서의 3대 병목

#### 병목 1: 일관성 유지

M1, M2, M3가 각각 다른 "너"를 이해하면 시스템이 붕괴한다.
→ MLPA는 이걸 해결하려는 시도. **포인트 정확함.**

#### 병목 2: 사용자 Drift

사용자는 변한다: 학기 초 vs 학기 중, 시험기간 vs 방학, 기분 좋을 때 vs 다운됐을 때.
이걸 반영 못하면 개인화는 **"과거의 나"에 고정**된다.

> **실제로 가장 큰 문제.**

#### 병목 3: 판단 구조의 학습

정보 압축, 기억 계층화, 규칙 전환까지는 설계되어 있다.
하지만 **"어떤 상황에서 개입해야 하고, 어떤 상황에서 놔둬야 하는지"** — 이 판단을 학습시키는 것이 가장 어렵다.

---

### 현재 짚은 포인트 검증

| 포인트 | 판정 |
|--------|------|
| 컨텍스트 문제 | ✅ 맞음 |
| 정보 축적 문제 | ✅ 맞음 |
| 규칙 전환 | ✅ 매우 중요 |
| 수렴 곡선 측정 | ✅ 연구적으로 탁월 |

**빠진 것:**

> **"행동 개입 정책(policy) 학습"** — 기억이 아니라 개입 정책이 핵심이다.

---

### 개인화의 3단계 모델

| Level | 설명 | 현재 위치 |
|-------|------|----------|
| Level 1 | **기억** — 나를 기억한다 | ✅ |
| Level 2 | **예측** — 내가 뭘 할지 예측한다 | ← 현재 |
| Level 3 | **개입** — 내가 망하기 전에 막는다 | 미래 |

## 대화 4: 우선순위 확정 — 편리함 우선

### [나] 답변

둘 다야. 편리함과 행동변화 둘 다 유도하고 싶은데 **편리함이 먼저**이긴 해.
행동변화는 사실 지금 예측할 만한 부분은 아니라고 생각하거든.

### [GPT] 방향 확정

> **1순위: 편리함 (즉각적인 가치)**
> 2순위: 행동 변화 (장기적 개입)

행동변화를 먼저 노리면 시스템이 "통제 장치"처럼 느껴지고 사용 지속성이 떨어진다.
편리함이 충분히 쌓이면 그 위에서 자연스럽게 개입이 가능해진다.

---

### "편리함"의 기술적 정의

| 구분 | 내용 |
|------|------|
| **(A) 입력 마찰 감소** | 짧게/애매하게 말해도 이해, 반복 설명 불필요 |
| **(B) 반복 작업 자동화** | 자주 하는 일정 자동 구조화, 선호 시간 배치, 에너지 기반 재조정 |
| **(C) 상황 인지 속도** | 지금 뭐 해야 하는지 즉시 제시, 집중/휴식 블록 자동 판단 |

---

### 편리함 관점의 핵심 병목: 입력 해석 안정성

> 한 번 잘못 해석 → 신뢰 깨짐
> 두 번 재질문 → 귀찮아짐
> 세 번 틀리면 → 사용 중단

MLPA의 Layer 0 규칙 전환은 곧 **"편리함 강화 엔진"**이다.

---

### 편리함 우선순위

1. **해석 정확도 상승**
2. **재질문 감소**
3. **자동 배치 성공률**

행동변화는 나중 문제.

---

### 구체적 전투 지점 3가지

#### 문제 1: 파싱 안정성

Confidence calibration은 좋은 설계지만, **카테고리 분류가 불안정하면 소용없다**.
→ "카테고리 Drift"부터 측정해야 한다.

#### 문제 2: 반복 입력의 구조화 (정규화 계층)

"빨래", "빨래해야지", "빨래 해야됨", "빨래 ㄱ" — 이걸 다 같은 작업으로 묶을 수 있어야 한다.
LLM 문제가 아니라 **정규화 계층** 문제.

#### 문제 3: Working Memory 정확성

"지금 해야 할 것" 추천이 틀리면 즉시 불편함.
→ **Layer 3 정확도가 핵심**.

---

### 편리함이 만드는 행동변화

편리함이 충분히 높아지면 행동변화는 **부작용처럼** 따라온다:
- 미루는 패턴 자동 감지
- 마감 임박 자동 경고
- 에너지 기반 재배치

→ 사용자는 점점 덜 망한다. **그것이 행동변화다.**

---

### GPT의 현실 전략 제안

**Step 1.** 하루에 가장 자주 입력하는 20개 유형을 뽑는다
**Step 2.** 그 20개를 Layer 0 규칙으로 고정한다
**Step 3.** 20개에 대해서는 0토큰 처리한다

→ 체감 편리함이 급상승한다.

---

### 편리함 KPI 정의 (필요)

| KPI | 설명 |
|-----|------|
| 평균 재질문 횟수 | 1회 입력당 재질문 수 |
| 자동 저장 성공률 | 확인 없이 저장된 비율 |
| 반복 작업 자동 인식률 | 기존 패턴과 매칭된 비율 |
| 사용자 수정 diff 비율 | 파싱 결과를 사용자가 수정한 비율 |

### GPT의 마지막 질문

> 시스템을 쓰면서 제일 짜증날 것 같은 순간은 언제야?
> **그 순간이 지금 해결해야 할 정확한 포인트다.**
