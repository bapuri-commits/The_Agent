- 모델 가중치를 수정할 수 없음 → **모든 개인화는 컨텍스트 주입으로만 달성**

## 2. 핵심 문제 (Research Question)

> **"컨텍스트가 폭발하지 않으면서, 딥러닝급에 준하는 성능으로
> 사용자(성향, 성격, 일상, 일정)를 깊게 이해시키는 방법은?"**

### 문제의 구조

```
개인화 깊이 ∝ 컨텍스트 양
그러나
컨텍스트 양 ↑ → 비용 ↑ + 성능 ↓ (lost in the middle) + 노이즈 ↑

무작정 컨텍스트를 늘리면 어느 시점부터 오히려 나빠진다.
```

### 기존 접근법의 한계

| 접근법 | 한계 |
|--------|------|
| **RAG** | "관련 조각"은 찾지만 전체적인 이해(holistic understanding)는 못 함 |
| **단순 요약** | 압축하면 뉘앙스 손실. "3번 미루다 자정에 작업"이 "가끔 미룸"으로 변질 |
| **파인튜닝** | 이상적이지만 API 모델에선 불가능하거나 매우 제한적 |
| **무한 컨텍스트** | 물리적 한계 + lost in the middle + 비용 폭발 |

## 3. 현재 설계: 4-Model Architecture

4개 모델이 각각 다른 역할을 수행:

| 모델 | 역할 | 호출 빈도 |
|------|------|----------|
| **[M1] Worker** (gpt-4o-mini) | 입력 파싱, 구조화. "생각 안 하는 처리기" | 고빈도 (하루 20~50건) |
| **[M2] Stabilizer** (Claude 3.5 Sonnet) | 언어 정리, 안정적 해석. 과확장 방지 | 중빈도 (하루 10~20건) |
| **[M3] Judge** (Claude Opus 4.6) | 판단, 개입, 설득, 차단. 삶의 운영 판단 | 희소 (하루 1~3건) |
| **[M4] Distiller** (Claude 3.5 Sonnet) | 장기 기억 정제. 노이즈 제거 요약 | 저빈도 (하루 1~2건) |

### 설계 원칙
- 모델은 절대 "나"가 아니다
- 기억은 외부 메모리 시스템이 관리한다
- 모델은 판단만 한다
- 플래그십 모델은 희소하게 호출한다
- **요약/정제 레이어 없이는 장기 개인화는 불가능하다**

---

## 4. 현재 설계: 4계층 메모리 아키텍처 (MLPA)

**Multi-Layer Personalization Architecture** — 인간 기억 구조에서 차용

### Layer 0: Procedural Memory (절차 기억) — 코드 규칙

- 학습된 패턴을 **코드 규칙으로 변환** (LLM 토큰 0 소모)
- 예: `"빨래" → {est_minutes: 40, energy: 2, preferred_time: "afternoon"}`
- M4 Distiller가 패턴 감지 → 자동 생성
- 크기: 무제한 (코드이므로)
- 갱신: 패턴 50건 축적 시

### Layer 1: Semantic Memory (의미 기억) — USER_PROFILE.md

- 사용자에 대한 확정된 이해
- **고정 크기 문서, 추가가 아닌 덮어쓰기** (M4가 재작성)
- 상한: ~500 tokens
- 갱신: 월 1회 (또는 큰 변화 감지 시)
- 예: "ADHD 심함, 오전 집중, 과제 해놓고 안 냄, 수강신청 까먹음"

### Layer 2: Episodic Memory (일화 기억) — pgvector (Phase 4)

- 과거 경험/사건 기록
- Phase 1~3: inbox_logs + audit_logs in DB
- Phase 4: pgvector 임베딩 → 관련 에피소드만 검색
- LLM에 직접 안 들어감 (검색 시에만 ~500 tokens)
- 크기: 무제한 (DB)

### Layer 3: Working Memory (작업 기억) — 실시간 DB 쿼리

- 매 요청마다 새로 계산
- 예: "pending task 5개, 오늘 2블록 완료, 다음 블록 14:00"
- 크기: ~300 tokens (고정)

### 각 모델이 보는 메모리

| 모델 | Layer 0 | Layer 1 | Layer 2 | Layer 3 | 총 토큰 |
|------|---------|---------|---------|---------|--------|
| M1 Worker | ✅ (코드) | ✅ | ❌ | ✅ | ~800 |
| M2 Stabilizer | ✅ (코드) | ✅ | 필요시 | ✅ | ~800~1,300 |
| M3 Judge | ✅ (코드) | ✅ | ✅ (검색) | ✅ | ~1,300~1,800 |
| M4 Distiller | 생성 | 생성 | 입력 | ❌ | 입력 많음, 출력 적음 |

**핵심: 어떤 모델도 2,000 토큰을 넘지 않는다.**

### 핵심 원칙

> **학습 = 축적이 아니라 증류(Distillation)**
> 
> MEMORY.md와 USER_PROFILE.md는 덮어쓰기된다.
> M4가 주기적으로 전체를 다시 써서 가장 정확한 현재 이해를 유지.
> 크기는 항상 상한선 이내.

## 5. Confidence Calibration (임계값 자동 조정)

### 구조

사용자 입력 시 M1이 confidence를 반환. 이 값의 신뢰도를 추적하여 임계값 자동 조정.

```
confidence >= 0.95 → 자동 저장 + 확인 메시지
confidence 0.80~0.95 → 제안 + 확인 요청
confidence < 0.80 → 재질문
```

### 보정 알고리즘

- 최근 50건 sliding window
- 실제 정답률(corrections 없는 비율) / M1 보고 confidence = calibration_ratio
- ratio > 1.1 (잘 맞추는데 겸손) → 임계값 0.05 내림
- ratio < 0.85 (못 맞추는데 과신) → 임계값 0.05 올림
- **카테고리별 독립 추적** (학교/개인/프로젝트)
- 2주 주기 재평가
- 초기값 0.95 (거의 항상 확인) → 점진적으로 내림

## 6. 학습 데이터 수집

### inbox_logs 테이블 (구현 완료)

모든 inbox 처리 과정을 학습 원본으로 저장:

| 필드 | 용도 |
|------|------|
| raw_input | 원본 입력 |
| input_hour, input_day_of_week | 시간대 패턴 |
| energy_estimate | 입력 시점 에너지 추정 |
| parse_result | M1 첫 파싱 결과 |
| confidence | M1 확신도 |
| clarifications | 재질문 목록 |
| user_responses | 사용자 답변 |
| final_result | 최종 확정 결과 |
| corrections | 사용자 수정 diff |

### 학습 데이터 활용 경로

```
[원본 + 파싱 + 재질문 + 답변 + 수정 diff]
    ↓
M4 Distiller (주기적 실행)
    ↓
├─ Layer 0 코드 규칙 생성 ("빨래" → {est:40, energy:2})
├─ Layer 1 USER_PROFILE.md 재작성
├─ Layer 2 에피소드 요약
└─ Calibration 재계산
    ↓
M1 시스템 프롬프트에 반영
    ↓
점점 재질문 감소, 정확도 향상
```

## 7. 연구 질문 (Research Questions)

### RQ1: 컨텍스트 압축의 최적 비율
- 원본 100 tokens → 압축 후 몇 tokens가 최적?
- 압축률과 판단 정확도의 관계는?
- 카테고리별 최적 압축률이 다른가?

### RQ2: 절차 기억(코드 규칙) 전환 시점
- 패턴이 몇 회 반복되면 코드 규칙으로 전환해도 안전한가?
- 잘못된 규칙을 감지하고 롤백하는 메커니즘은?
- 코드 규칙 vs 컨텍스트 주입의 정확도 차이는?

### RQ3: 장기 개인화의 수렴 곡선
- 데이터 N건 축적 시 개인화 정확도의 이론적 상한은?
- 어느 시점에서 추가 데이터의 한계효용이 급감하는가?
- 딥러닝 파인튜닝 대비 컨텍스트 주입의 성능 격차는?

### RQ4: 에피소드 검색의 최적 전략
- Top-K 검색에서 K는 몇이 최적?
- 시간 가중치 vs 유사도 가중치의 균형?
- 에피소드 임베딩의 최적 chunk 크기?

### RQ5: 다중 모델 간 컨텍스트 일관성
- M1, M2, M3가 같은 사용자를 다르게 이해할 위험은?
- 계층형 메모리가 단일 모델 대비 일관성에 미치는 영향?

## 8. 실험 계획

### Phase 1~2 (현재, 구현 중)
- inbox_logs 수집 시작 ✅
- USER_PROFILE.md 수동 작성 ✅
- Confidence calibration 기초 데이터 축적

### Phase 3 (개강 후)
- 학교 데이터 유입 → 패턴 다양화
- Layer 0 코드 규칙 첫 자동 생성 시도
- **RQ1 실험**: 압축 비율 변화에 따른 판단 품질 A/B 테스트

### Phase 4 (학기 중)
- pgvector 도입 → Layer 2 에피소드 검색
- M4 Distiller 본격 가동
- **RQ2 실험**: 코드 규칙 전환 임계값 탐색
- **RQ3 실험**: 주간 개인화 정확도 추적 (수렴 곡선 관찰)

### 성공 기준

| 지표 | 3개월 | 6개월 | 12개월 |
|------|-------|-------|--------|
| M1 파싱 정확도 (수정 불필요 비율) | 60% | 80% | 90%+ |
| 재질문 빈도 | 매번 | 2건 중 1건 | 5건 중 1건 |
| 컨텍스트 크기 (M3 기준) | ~1,500 tok | ~1,800 tok | ~2,000 tok (상한) |
| 코드 규칙 자동 생성 수 | 0 | ~10개 | ~50개+ |
| 사용자 체감 "나를 이해한다" | 낮음 | 중간 | 높음 |
