# The Agent — 개발 워크플로우

> 매 Phase는 별도 대화창에서 진행한다.
> 이 문서는 모든 Phase/Step에서 반드시 따르는 프로세스를 정의한다.

---

## Phase 프로세스

```
Phase 시작
  │
  ├─ 1. Step 쪼개기
  │     Phase 목표를 구체적 Step으로 분해
  │     각 Step의 범위, 산출물, Done 정의 확정
  │
  ├─ 2. Step 루프 (각 Step마다 반복)
  │     │
  │     ├─ a. 설계 논의
  │     │     - 이번 Step에서 만들 것의 설계를 논의
  │     │     - 사용자 의도 확인, 의문점 질문
  │     │     - 합의될 때까지 구현 시작하지 않음
  │     │
  │     ├─ b. 구현
  │     │     - 합의된 설계대로 코드 작성
  │     │     - 구현 완료 후 무조건 멈춤 (자동 진행 금지)
  │     │
  │     ├─ c. 감사 (Audit)
  │     │     - 작성된 코드 전수 검사
  │     │     - 버그, 누락, 설계 불일치, 엣지케이스 확인
  │     │     - 문제 발견 시 즉시 전부 수정
  │     │
  │     ├─ d. 테스트
  │     │     - 자동 테스트: AI가 실행 가능한 테스트 수행
  │     │     - 수동 테스트: 사용자가 해야 할 테스트 리스트 반환
  │     │     - 결과 확인 후 문제 있으면 수정
  │     │
  │     ├─ e. 사용자 피드백
  │     │     - 추가 요구사항 수집
  │     │     - 없으면 다음 Step 진행
  │     │
  │     └─ (다음 Step으로)
  │
  ├─ 3. Phase 종료 감사
  │     - 전체 코드 감사 + 통합 테스트
  │     - Phase 목표 달성 여부 확인
  │     - 잔존 이슈 목록화
  │
  └─ 4. 다음 Phase 프롬프트 작성
        - 다음 대화창에서 사용할 핸드오프 프롬프트
        - 현재까지의 전체 컨텍스트 + 결정 사항 + 코드 상태 포함
        - PHASE_PROMPT_{N}.md로 저장
```

## Step 내부 상세

### a. 설계 논의

```
[AI]  이번 Step의 설계 제안 + 질문
[USER] 피드백 / 수정 / 승인
[AI]  최종 설계 확정 요약
[USER] "진행해" → 구현 시작
```

- 사용자가 "진행해"라고 할 때까지 구현 시작 금지
- 설계에 애매한 부분이 있으면 반드시 질문

### b. 구현

- 합의된 설계만 구현 (범위 초과 금지)
- 구현 완료 후 변경된 파일 목록 + 요약 제시
- **자동으로 다음 Step 진행하지 않음**

### c. 감사 (Audit)

체크리스트:
- [ ] 설계와 코드가 일치하는가?
- [ ] 누락된 기능이 있는가?
- [ ] 에러 핸들링이 충분한가?
- [ ] 기존 코드와 충돌하지 않는가?
- [ ] 보안 문제가 없는가?
- [ ] 타입/스키마가 올바른가?

### d. 테스트

두 종류로 구분하여 반환:

```
=== 자동 테스트 (AI 실행) ===
1. [테스트 내용] → ✅/❌ 결과

=== 수동 테스트 (사용자 실행) ===
1. [테스트 내용] — 방법: [구체적 절차]
2. [테스트 내용] — 방법: [구체적 절차]
```

### e. 사용자 피드백

- "없음" / "LGTM" → 다음 Step
- 수정 요청 → 수정 후 다시 c~d 반복

## Phase 프롬프트 구조

다음 Phase 시작 시 새 대화창에 넣을 프롬프트 (`PHASE_PROMPT_{N}.md`):

```markdown
# Phase {N} 프롬프트

## 프로젝트 컨텍스트
- 프로젝트 경로: G:\CS_Study\The_Agent
- 설계 문서: docs/ 디렉토리
- 현재 상태: Phase {N-1} 완료

## 이전 Phase 요약
- 완료된 것: ...
- 결정된 것: ...
- 알려진 이슈: ...

## 이번 Phase 목표
- ...

## 코드 상태
- 작동 중인 기능: ...
- 파일 구조: ...

## 워크플로우
docs/WORKFLOW.md 참조. 반드시 이 프로세스를 따를 것.

## 시작 지시
Step 쪼개기부터 시작하세요.
```

## 규칙 요약

1. **구현 후 자동 진행 금지** — 반드시 멈추고 감사
2. **설계 합의 전 코현 금지** — "진행해"가 나올 때까지
3. **테스트는 자동+수동 분리** — 수동 테스트는 리스트로 반환
4. **Phase 간 핸드오프** — 프롬프트 문서로 컨텍스트 전달
5. **문제 발견 시 즉시 수정** — 다음 Step으로 넘기지 않음
