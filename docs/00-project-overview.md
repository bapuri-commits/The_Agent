# 00 — Project Overview (v2)

> **v2 재설계: 2026-02-15**
> "스마트 할일 앱" → "내 디지털 생활에 깊숙이 통합된 AI 비서"로 비전 확장.

## 프로젝트명
**The Agent** — Personal AI Secretary (ADHD-friendly, Performance-first)

## 한 줄 요약
ADHD 환경에서 학교 + 일상 전반의 정보를 **자동 수집 → 구조화 → 계획 → 실행 지원 → 마무리**까지 end-to-end로 커버하는 AI 비서 시스템.

---

## 왜 만드는가

### 구체적 문제 상황
- 컴공 4학년, ADHD → 일정/할 일 관리가 구조적으로 불가능
- **과제를 해놓고 제출을 안 해서** 점수를 낮게 받음 (한두 번이 아님)
- **수강신청 미리담기를 매번 까먹음** (4학년인데 아직도)
- 학교 공지를 안 봐서 중요한 일정을 놓침
- 할 일 정리 자체를 못 함 → 뭘 해야 하는지도 모르는 상태가 됨
- 기존 할 일 앱(Todoist, Notion 등)은 "기록"은 되지만 "실행"까지 이어지지 않음
- AI 챗봇의 "조언"은 참고만 하고 끝남 → 행동 변화 없음

### 필요한 것
- 정보를 **자동으로 알아서** 알맞은 것들로 제시
- 그것을 **정리해서 보여주고**
- 내가 **처리할 수 있도록** 도와주고 (시간 관리, 방향성)
- **마무리까지** 추적 (제출 확인, 후속 일정 조정)

## 핵심 원칙 (8가지)

### 1. SSOT (Single Source of Truth)
- 구조화된 데이터베이스가 유일한 진실의 원천
- 대화 로그나 외부 시스템이 아니라, 우리 DB에 있는 것만 진실

### 2. Deterministic Planning (결정론적 계획)
- 같은 입력 → 같은 출력
- 우선순위 점수는 명시적 수식으로 계산, LLM이 결정하지 않음
- 입력 = (tasks 상태 + calendar_blocks + user_profile + 현재시각)

### 3. LLM 역할: 확장된 보조자
- **하는 것:** 텍스트 구조화, 작업 분해, 정보 요약/정리, 노트 작성 보조, 컨텍스트 기반 안내
- **하지 않는 것:** 우선순위 결정, 일정 배치, 규칙 적용 (코드가 담당)
- 이유: 재현성, 비용 통제, 환각 방지 + 성능 최우선

### 4. Execution Support (실행 지원)
- "하면 좋겠다"가 아니라 "지금 이것을 해라"
- 직접 대신 해주는 게 아니라, **최종 클릭 직전까지 안내**
  - 예: "LMS 제출 페이지 → 제출할 파일 → 제출 확인 리마인더"
- 항목마다 관여 범위가 다름 (일상 task vs 학교 과제)

### 5. Capture Friction ≈ 0 (입력 마찰 제로)
- 웹 UI에서 자연어 한 줄이면 끝
- 부족한 정보는 기본값 자동 채움 + 확인 질문

### 6. Failure-safe (실패 안전)
- 모델이 틀려도 시스템은 무너지지 않음
- Fallback 모드: Minimal Plan / Urgent Only / Recovery

### 7. Deep Integration (깊은 통합) — 신규
- 학교 시스템 (e-Class, nDRIMS, 학교 포탈, 학과 사이트)
- 옵시디언 (The Record 볼트 읽기/쓰기)
- 정보를 자동으로 수집해서 task/event로 구조화

### 8. Pattern Learning (패턴 학습) — 신규
- 사용자의 에너지, 집중, 습관, 스케줄 패턴을 학습
- 학습 결과를 스케줄 최적화에 반영
- 단일 사용자이므로 개인화 극대화 가능

## 5단계 플로우 (v1의 4대 플로우에서 확장)

```
1. Gather (수집)
   - 학교 시스템에서 과제/시험/공지 자동 수집
   - 옵시디언에서 기존 기록/맥락 참조
   - 사용자 수동 입력 (1줄 자연어)

2. Organize (구조화)
   - LLM이 수집된 정보를 task/event로 구조화
   - 기본값 자동 채움 + 확인 요청
   - DB에 저장 (SSOT)

3. Plan (계획)
   - 결정론적 우선순위 계산 (코드)
   - Today Plan: free window에 task 블록 배치
   - 에너지/집중 시간대 매칭

4. Support (지원)
   - 시간 관리 안내 ("지금 이걸 하세요")
   - 방향성 제시 ("이 과제는 이 순서로 하면 됩니다")
   - 필요한 링크/파일/정보 제공

5. Follow-up (마무리)
   - 미이행 감지 → Enforcement (Narrowing → Commitment → Escalation)
   - 제출 확인 리마인더
   - 후속 일정 자동 조정
   - 완료 기록 → 패턴 학습 데이터 축적
```

## 성능 정의

"성능"은 모델 지능이 아니라 다음 지표의 합이다:

| # | 성능 지표 | 의미 |
|---|----------|------|
| 1 | 정보 도달률 | 놓치는 공지/마감 없이 사용자에게 전달되는가 |
| 2 | 실행 성공률 | 사용자가 실제로 행동했는가 (과제 제출, 일정 준수) |
| 3 | 일정 안정성 | 같은 조건에서 계획이 흔들리지 않는가 |
| 4 | 컨텍스트 깊이 | 사용자의 상황/패턴을 얼마나 정확히 이해하는가 |
| 5 | 마찰 최소화 | 입력~응답이 얼마나 빠르고 쉬운가 |
| 6 | 실패 복구 | 장애 시 graceful degradation |
